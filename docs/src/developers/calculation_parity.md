# Calculation parity record

Reference v2 is frozen at commit `a1a7fb71d6ac189ddf06d58e2817dc4197dd4031`
(`a1a7fb7`). The 33 networks include sources, passive AC/DC circuits,
lines, cables, YY and Dyn11 transformers, machines, TLC and MMC controls,
energy control, modulation, filters, the IEEE 39-bus system, and the larger
HVDC and converter-machine examples.

`test/reference/v2/metadata.txt` records the source commit, package versions,
dependency-manifest hash, numeric and label hashes, test-case names, frequency
axis, and omitted calculations. The generator is retained under
`test/reference/` for the frozen source API. The current comparison builds
networks from `test/parity/fixtures.jl` using direct models and named ports.
Reference files are not regenerated by the tests.

## Numerical comparisons

Run `julia --project=. test/parity_test.jl`. The test checks source and format
metadata, data hashes, fixture order, stored omissions, array sizes, labels,
converted power-flow data, solved values, state matrices, and frequency responses.
Calculations use one BLAS thread. The frequency axis is 0.001, 1, 5, 49, 150,
500, 1500 and 5000 Hz. Responses use angular frequency in rad/s.

Reference v2 was frozen with Julia 1.12.7 (`julia_version`) and a dependency
manifest identified by its SHA-256 (`dependency_manifest_sha256`) in
`test/reference/v2/metadata.txt`.
Numerical comparisons in `test/parity_test.jl` and the frozen operating-point
checks of `test/terminal_values_test.jl` run only when the running Julia version
and root `Manifest.toml` match these records, because newer solver packages
converge to steady states that differ within the solver tolerance but far above
the parity tolerances.
With another Julia version or a freshly resolved environment such as CI, the
tests report both environments and skip those comparisons while still checking
the metadata and data hashes.

Each numeric comparison uses `abs(live - reference) <= atol + rtol*abs(reference)`:

| Dataset | Relative tolerance | Absolute tolerance |
|:--|--:|--:|
| Converted power-flow data (`pm`) | `1e-15` | `1e-15` |
| Node/domain mappings (`nodes`) | `0` | `0` |
| Power-flow solution and operating point (`pf`, `op`) | `1e-12` | `1e-12` |
| State-space matrices (`ss`) | `1e-10` | `1e-12` |
| Eigenvalues (`eig`) | `1e-8` | `1e-12` |
| Component, nodal and edge admittance (`y`, `ynode`, `yedge`) | `1e-12` | `1e-12` |
| Reduced impedance and stability (`zdet`, `stability`) | `1e-12` | `1e-12` |
| Control-equation checks and PSCAD comparison rows (`oracle`, `pscad_op`) | `1e-12` | `1e-12` |

The test prints maximum absolute and relative differences per dataset and per
test-case family. These limits compare the refactor with stored calculations. Agreement with measured
equipment or an EMT response requires separate measurements.

The comparison accounts for newly solved power flow in the small AC circuit
(`small_ac`), passive overhead line (`passive_ohl`), YY and Dyn11 transformers
(`transformer_yy`, `transformer_dy`), DC circuit (`dc`) and DC cable (`dc_cable`).
These cases formerly recorded power flow as unnecessary. Their current solutions
require local solves. Additional zero generator-power seeds are checked as
zero. Stored droop state and output arrays for the removed keyword construction are
retained in the reference but omitted from live comparison. The listed arrays
are checked for presence in the reference and absence from live data.

## Net names and port values

`test/parity/names.jl` reads the previous topology rows from
`test/parity/topology_08f3d2e.tsv`. `net_map` matches each row by
`(component, port, terminal)` and checks that row order, bus number, electrical
domain and frame are unchanged. Nongrounded nets map one to one. A grounded
net may split into coordinate-specific ground names. Different old nets remain distinct. `mapped_datasets` applies this map to node and bus dataset keys.
`retained_nets` checks the ordered nodes used for reduced responses.

Physical operating values are grouped by component and named port. Powers and
signed currents are positive into each component, as in `Y = I_in / V`.
The comparison maps live `ACPortValues` and `DCPortValues` to the stored
field names and power signs before comparing them. Source and synchronous-machine generation
and converter AC delivery have negative port powers.

## PSCAD names and polarity

`test/parity/pscad_test.jl`, included by `test/pscad/run_xml_tests.jl`, compares
fresh local exports with the frozen PSCAD graphs and probe lists. It checks
electrical graph equivalence with `PSCADTopology.equivalent` after applying the
name and meter-polarity maps. It runs locally.
The test-case list in reference metadata selects 27 exports from the 33 networks.

`test/pscad/probe_names.jl` maps former numeric current-probe suffixes to named
ports. Converters map 1 to `dc` and 2 to `ac`. Two-port passives map 1 to
`side1` and 2 to `side2`. One-port devices use `ac` or `dc`. The resulting names
are `I_<element>_<port>`. `test/parity/names.jl` also maps voltage-probe names
when the derived bus name changes. Generated
component identifiers follow the mapped component name and PSCAD's length limit.

Every new current probe measures into its component. The polarity map reverses
meters that formerly measured outward: AC sources, synchronous machines,
converter AC ports, and the second port of nongrounded passive branches.
The graph comparison swaps those meter terminals. Stored synthetic comparison
rows also map channel names and negate machine and converter P/Q values where the
meter direction changed. Probe names, graph wiring and comparison values are
checked together.
